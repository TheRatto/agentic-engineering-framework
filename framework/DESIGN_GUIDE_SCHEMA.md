# DESIGN_GUIDE_SCHEMA.md

## Purpose

This document defines the standard structure for `DESIGN_GUIDE.md`.

`DESIGN_GUIDE.md` captures project-level visual language and interaction style so
UI work remains coherent while allowing intentional differentiation.

---

## Required Sections

## Visual Positioning

- Product personality attributes (3-5 adjectives)
- Design intent statement (short paragraph)
- Distinctive motifs to emphasize
- Anti-patterns to avoid for this project

---

## Color System

- Core palette (primary, secondary, neutral)
- Semantic colors (success, warning, error, info)
- Contrast expectations and accessibility notes
- Explicit rationale for palette choices

---

## Typography

- Type scale and hierarchy
- Usage rules by context (headline, body, caption, UI labels)
- Density/readability guidance

---

## Spacing and Layout Rhythm

- Spacing scale
- Layout principles (alignment, grouping, visual rhythm)
- Breakpoint-level layout intentions (if applicable)

---

## Component Tone and Behaviour

- Component style direction (buttons, cards, forms, nav)
- Interaction tone (motion, feedback, transitions)
- States that must be visually distinguishable

---

## Differentiation Rules

- What makes this UI recognizably "ours"
- Where novelty is encouraged
- Where convention must be preserved

---

## Accessibility Baseline

- Minimum contrast expectations
- Focus visibility rules
- Keyboard and assistive tech expectations

---

## Platform Considerations

- Platform-specific adjustments (web, iOS, Android, desktop)
- Links to platform guidance used
- Notes on adapted vs adopted patterns

---

## Maintenance Rules

- Keep `DESIGN_GUIDE.md` updated when UI direction changes
- Keep design decisions aligned with `UI_SPEC.md` and `UX_RATIONALE.md`
- Avoid implementation-level details (no CSS classes, file paths, framework APIs)
